# integrity

Tamper checks: `protectedSet(git, input).hash()` before a step and after it; `tamperChanges(before, after)` lists every protected file that changed. A `hash()` error means the set could not be read whole: never compare it.
Protected: shared git config, hooks, info/attributes and info/exclude, the worktree's git config and HEAD, the item branch's commit, `.gitattributes`, `.tokama/`, the base commit's test files and snapshots, test config, package config, CI files and lockfiles (`protected.ts`). Git config files count by the entries git reads from them, without the remote and tracking keys a `git push -u` or `git remote set-url` writes (`IGNORED_KEYS` in `tamper.ts`; a remote url or pushurl only under a plain remote name and when it names a network host, never a local path or a transport helper). `sharedGitHashes` hashes the shared git dir's entries alone, without reading any worktree, plus the content of the files they include (`include.path`, `includeIf.*.path`); an include that cannot be read makes `hash()` an error.
Symlinks are hashed by target and never followed. Records name files by area and relative path, never absolute paths.
Must not restore files or stop an item: the caller decides what a tamper event does.

Change and risk: `readChange(git, dir, base, to)` counts one diff as files, lines and the number of files of each kind (`ChangeSummary`; counts only, never paths). `sensitive.ts` is the one table of sensitive kinds (dependencies, migrations, CI, infrastructure, secrets and settings, sign-in code) and of test files, matched on lowercase repo-relative paths; some rows belong to one kind of repo, found from marker files in the base commit and from the extensions of the changed files. `risk(facts)` is a pure function: high when a rule says so (reasons in rule order), low otherwise, not rated when the change could not be counted. The engine stores the facts and calls `risk` each time an item is read, so a changed rule needs no migration. No AI takes part.
